Abstractly, the Event Loop and the Worker Pool maintain queues for pending
events and pending tasks, respectively. In truth, the Event Loop does not
actually maintain a queue. Instead, it has a collection of file descriptors that
it asks the operating system to monitor, using a mechanism like epoll (Linux),
kqueue (OSX), event ports (Solaris), or IOCP (Windows). These file descriptors
correspond to network sockets, any files it is watching, and so on. When the
operating system says that one of these file descriptors is ready, the Event
Loop translates it to the appropriate event and invokes the callback(s)
associated with that event. You can learn more about this process here . In
contrast, the Worker Pool uses a real queue whose entries are tasks to be
processed. A Worker pops a task from this queue and works on it, and when
finished the Worker raises an "At least one task is finished" event for the
